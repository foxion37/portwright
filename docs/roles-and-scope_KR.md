# 역할과 활동 범위

portwright는 AI 에이전트가 외부 도구의 현재 절차와 재사용할 교훈을 찾도록 돕습니다. 불필요한 설정을 사용자에게 다시 시키거나 같은 실패를 반복하지 않도록, 로컬 CLI가 개인 캐시를 읽습니다. 공유 Hub는 **M2와 M3의 계획**이며, 현재 릴리스에서 사용할 수 있는 기능이 아닙니다.

## 누가 무엇을 하나요?

- **User(사용자):** 외부 개발자, 회사 동료, AI 앱을 통해 portwright를 쓰는 비개발자를 모두 포함합니다. 동의처럼 사람만 할 수 있는 단계는 사용자가 직접 수행합니다.
- **Agent(에이전트):** Client 안에서 도구 사용을 결정하는 AI입니다. 관련 Procedure와 Lesson을 읽고, 없거나 낡은 절차는 도구의 현재 공식 문서에서 도출해 캐시합니다. 에이전트 몫의 실행에는 portwright가 아닌 별도 연결 백엔드를 씁니다.
- **Client(클라이언트):** Agent를 실행하는 앱입니다. MCP를 지원하는 코딩 도우미 등이 portwright를 설치하거나 호출하며, 자체 권한 제어를 유지합니다. portwright의 행동 등급은 조언일 뿐 강제가 아닙니다.
- **Operator(운영자):** 계획된 공개 Hub의 초대 토큰을 발급하고, `stable` 승격을 검토하며, `stable` revision의 회수를 확인합니다.
- **회사 관리자:** 계획된 회사 Hub의 초대 토큰을 발급하고 회사 사용자에게 접근 권한을 부여합니다. 회사 배포와 저장소 권한을 확인한 뒤에만 회사 Hub를 구축하며, 그곳에서도 운영자가 `stable` 회수를 확인합니다.

## 코드와 지식은 어디에 있나요?

저장소 세 종류의 역할을 나눕니다. **비공개 작업 저장소**에서는 CLI와 Hub 코드를 개발하고 소유자의 개인 콘텐츠를 보관합니다. **공개 배포 저장소**에는 검사한 산출물만 한 방향으로 내보냅니다. v2.1까지는 배포 가능한 노트도 함께 싣습니다. M2에서 commons를 이 노트들로 한 번 채운 뒤부터는 코드만 내보냅니다. **비공개 commons 저장소**에는 한 Hub가 공유하는 Procedure/Lesson 캐시의 정본 git 사본, 등급, 회수 표식을 둡니다. 회사 Hub에는 별도의 비공개 commons를 둡니다. commons는 미리 채운 등록소가 아닙니다. 중앙 절차가 없거나 낡았다면 공식 문서에서 다시 도출해 캐시합니다.

배달 대상도 셋으로 구분합니다. **personal** 배달은 소유자의 기존 개인 카탈로그와 개인 스킬을 유지하며, 공개·회사 토큰으로는 접근할 수 없습니다. **public Hub**는 별도의 Worker, D1 접수함, 처음에는 비어 있는 배달 버킷을 쓰는 초대제 공유 서비스로 계획되어 있습니다. **company Hub**는 나중에 별도 자격증명, 저장 공간, commons로 배포할 예정입니다. 각 공유 Hub는 콘텐츠를 나르기 위해 Worker 한 개, D1 한 개, Actions workflow 한 개를 씁니다. 어느 Hub도 사용자의 외부 도구 호출을 대신 실행하지 않습니다. 공개 Hub와 회사 Hub 사이에 대체 조회는 없으며, 개인 카탈로그는 두 공유 Hub로 옮기지 않습니다.

## 읽고 제출하는 방법

로컬에서는 같은 노트 id를 `_private` → 추적 노트 → `_hub` 순서로 찾습니다. 같은 출처 안에서 id가 중복되면 오류가 나고, 출처가 다르면 우선순위에 따라 덮어쓰면서 경고합니다. `_hub`는 Hub에서 받은 노트를 저장하는, git이 추적하지 않는 로컬 캐시로 계획되어 있습니다. 코드 업데이트와 별개로 동기화합니다. 캐시에 절차가 없으면 Agent가 현재 공식 문서에서 도출해 저장합니다. 전달받은 노트를 읽기 위해 사용자가 비공개 commons 저장소에 접근할 필요는 없습니다.

계획된 공유 Hub에서는 `stable` 노트만 기본 preflight, 번들, MCP 조회에 나옵니다. 게시 검사를 통과한 `trial` 노트는 시험 중인 자료로, 명시적으로 요청해야만 볼 수 있습니다. 자동 게시가 검증 완료를 뜻하지는 않습니다. 서로 다른 초대 토큰 계보 세 건의 확인에 Operator 검토까지 마쳐야 `stable`로 올립니다. 본문 revision이 바뀌면 다시 확인해야 합니다. 서로 다른 두 계보가 신고하면 `trial` revision을 회수하고, `stable` 회수에는 Operator 확인이 필요합니다. 회수는 노트 id와 revision digest를 기준으로 현재 조회, 옛 릴리스 pin, 동기화한 로컬 캐시에 적용합니다. 오프라인 캐시는 다시 연결해 동기화하기 전까지 새 회수 사실을 알 수 없습니다.

제출은 **M2에서 MCP로만 제공할 계획**입니다(`submit_lesson`, `confirm_lesson`, `report_failure`). GitHub Issue/PR의 자유 본문 제출은 지원하지 않습니다. 공개 Hub의 토큰은 Operator가, 회사 Hub의 토큰은 회사 관리자가 발급하며, 직접 가입할 수 없습니다. 초대 토큰은 Hub 인증에만 사용하고 사용자의 외부 도구 자격증명으로 쓰지 않습니다. Hub에는 토큰의 해시, 조직, 권한(`read|submit|operator`), 만료, 비식별 계보 id만 저장하고 이름, 이메일 주소, IP 주소는 저장하지 않습니다.

## 지키는 경계

portwright는 외부 도구를 쓰는 방법을 기록하지만 자격증명 값이나 원본 출력은 기록하지 않습니다. 지원하는 제출에 대한 정확한 보장 범위는 **지원 제출 경로의 로컬 사전 검사 + 중앙 영속 저장·모델 전송 전 재검사 + 거부 원문 미보관**입니다. 패턴 검사는 가능한 모든 비밀이나 식별자를 찾아낸다는 뜻이 아닙니다. 자격증명 값, 원본 파일, 로그를 제출하지 마세요. Hub는 자유 텍스트 필드를 D1에 저장하거나 모델에 보내기 전에 다시 검사하고, 거부한 원문을 저장소나 로그에 남기지 않습니다. 노트에 식별 정보를 적지 마세요. 비공개 작업 저장소, 개인 스킬, 개인 프로파일은 공유 콘텐츠가 아닙니다.

portwright는 사용자의 외부 서비스 토큰, API 키, 환경변수 값을 저장하거나 전송하지 않습니다. 사용자 대신 외부 도구를 실행하거나 외부 도구 호출을 통제하는 게이트웨이로 작동하지 않으며, 정책을 강제로 집행하지 않습니다. 사용자 식별 정보를 수집하거나 원본 파일·로그를 업로드받지도 않습니다. Hub 인증용 초대 토큰은 인증 헤더로 보내는 제한된 예외입니다. Hub의 접수 인증과 게시 검사는 외부 도구 호출을 통제하는 게이트웨이가 아닙니다. 게이트웨이, 정책 집행, 감사 파이프라인은 계속 미뤄 둡니다. 공개·회사 Hub를 합친 모델 비용은 호출 전에 비용을 예약해 **월 USD 20**을 넘기지 않도록 계획했습니다. Cloudflare와 매시간 비정시 분에 실행하는 Actions도 무료 한도 안에서 운영할 계획입니다. 모델 예산을 모두 쓰면 분석과 신규 게시를 멈추지만 조회와 회수는 계속합니다. 다만 플랫폼 무료 한도가 소진돼도 온라인 조회가 끊기지 않는다고 보장하지는 않습니다.
